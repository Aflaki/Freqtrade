# انتقال Signal Relay به سرور جدید

این راهنما **سایت** (پنل، دیتابیس، کاربران، کلیدها، تنظیمات) را به سرور جدید می‌برد و بعد از سرور قدیم پاکش می‌کند.
ربات‌های Freqtrade، سشن‌های tmux و نگهبان (relay-watchdog) دست نمی‌خورند.

---

## مرحله ۰ — آماده‌سازی (چند روز قبل) ⚠️ مهم

کلیدهای API کاربران در صرافی **به IP سرور قدیم قفل است**. اگر بدون خبر جابه‌جا شوید، همه معاملات کاربران با خطای `-2015` رد می‌شود.

۱. سرور جدید (Debian 12) را بگیرید و IP آن را یادداشت کنید (مثلاً `NEW_IP`). پورت‌های ۸۰ و ۴۴۳ باید باز باشد.

۲. در سایت فعلی: **مدیریت ← تنظیمات و فرمول ← راهنماها و ویدیوها ← IP سرور**، هر دو IP را با کاما بنویسید:
```
65.109.188.248, NEW_IP
```
از این لحظه راهنماها و فرم صرافی به کاربران هر دو IP را نشان می‌دهند.

۳. به همه کاربران پیام بدهید (**مدیریت ← کاربران ← پیام همگانی تلگرام**؛ به کاربرانی که تلگرام را وصل نکرده‌اند جداگانه ایمیل بزنید). متن پیشنهادی:
> سایت تا تاریخ … به سرور جدید منتقل می‌شود. لطفاً در تنظیمات کلید API صرافی (Edit restrictions ← IP access) آی‌پی جدید **NEW_IP** را **علاوه بر** آی‌پی فعلی اضافه کنید. آی‌پی قبلی را پاک نکنید. راهنما: سایت ← راهنماها ← بایننس.

۴. (پیشنهادی) اگر دامنه واقعی بگیرید (مثلاً `panel.example.com`)، انتقال‌های بعدی خیلی ساده‌تر است: فقط DNS را عوض می‌کنید و وبهوک‌ها و ورود با گوگل عوض نمی‌شوند. با آدرس رایگان `sslip.io` آدرس با IP عوض می‌شود.

---

## مرحله ۱ — جابه‌جایی (حدود ۱۵ دقیقه؛ در این مدت کپی معاملات انجام نمی‌شود)

**روی سرور قدیم:**
```bash
bash /opt/signal-relay/deploy/update.sh
```
```bash
bash /opt/signal-relay/deploy/backup.sh --stop
```
سایت متوقف می‌شود (تا دو نسخه همزمان کار نکنند) و یک فایل `/root/signal-relay-backup-….tar.gz` ساخته می‌شود.
⚠️ این فایل شامل `secrets.json` است (کلید رمزگشایی API کاربران) — آن را جایی عمومی نگذارید.

فایل را به سرور جدید بفرستید:
```bash
scp /root/signal-relay-backup-*.tar.gz root@NEW_IP:/root/
```

**روی سرور جدید:**
```bash
apt update && apt install -y curl
```
```bash
curl -fsSLO https://raw.githubusercontent.com/Aflaki/Freqtrade/main/deploy/install.sh
```
```bash
bash install.sh --restore /root/signal-relay-backup-XXXX.tar.gz
```
(با دامنه: `bash install.sh panel.example.com --restore /root/…`)

همه چیز برمی‌گردد: کاربران، رمزها، سبدها، کلیدهای API، ربات‌ها، کاتالوگ ارزها، تاریخچه، تنظیمات، توکن تلگرام. آدرس سایت خودکار عوض می‌شود و IP قدیم از لیست IP کاربران حذف می‌شود.

---

## مرحله ۲ — وصل کردن همه چیز به آدرس جدید

۱. **وبهوک ربات‌ها:** در سایت جدید ← مدیریت ← وضعیت ربات ← دانلود `freqtrade_webhooks.py`. روی **هر دو** سرور ربات:
```bash
python3 freqtrade_webhooks.py --apply
```
بعد در پنل «بارگذاری مجدد کانفیگ همه ربات‌ها» را بزنید.

۲. **نگهبان:** در سایت جدید ← مدیریت ← مانیتورینگ سرورها، دستور نصب را کپی و روی **هر دو** سرور ربات اجرا کنید (وضعیت قبلی نگهبان حفظ می‌شود، فقط آدرس سایت عوض می‌شود).

۳. **تلگرام:** کاری لازم نیست (همان ربات است). اگر «ورود با تلگرام» دارید: در BotFather دستور `/setdomain` و دامنه جدید.

۴. **ورود با گوگل/اپل/…:** مدیریت ← ورود و امنیت؛ آدرس‌های بازگشت جدید را در کنسول هر سرویس جایگزین کنید.

۵. **نوتیفیکیشن گوشی:** آدرس جدید یعنی وب‌اپ جدید؛ روی هر گوشی سایت جدید را دوباره Add to Home Screen و نوتیفیکیشن را فعال کنید.

۶. **بررسی:** مانیتورینگ سرورها (هر دو سرور «فعال»؟)، «ارسال هشدار آزمایشی»، و در یک سبد «بررسی API و موجودی».

---

## مرحله ۳ — پاک کردن از سرور قدیم

وقتی مطمئن شدید سایت جدید درست کار می‌کند:
```bash
bash /opt/signal-relay/deploy/uninstall.sh
```
یک بار `DELETE` تایپ می‌کنید. قبل از پاک کردن یک نسخه پشتیبان آخر در `/root` ساخته می‌شود.
پاک می‌شود: سرویس، برنامه و داده‌ها، کاربر سیستمی، کار پشتیبان روزانه، و سایت از Caddy.
**دست نمی‌خورد:** ربات‌های Freqtrade، tmux، کانفیگ‌ها و نگهبان.

فایل پشتیبان را یک جای امن بیرون از سرور هم نگه دارید.

---

## اگر مشکلی پیش آمد (بازگشت)
روی سرور قدیم سایت را دوباره روشن کنید:
```bash
systemctl enable --now signal-relay
```
و روی سرور جدید متوقفش کنید:
```bash
systemctl disable --now signal-relay
```
وبهوک‌ها تا وقتی در مرحله ۲ عوض نشده‌اند هنوز به سرور قدیم می‌روند.
